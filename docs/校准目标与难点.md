# 画板校准：目标、初始状态与难点

> 本文记录「霸王茶姬」小程序画板的自动校准目标、真机/PC 窗口的初始状态，以及现有探测逻辑的主要难点。用于后续校准逻辑重构时对齐上下文。

## 1. 校准目标

自动校准需要在小程序画板窗口内定位以下控件（截图坐标系，逻辑尺寸 499×979）：

| 目标 | 状态 | 位置（展开态） | 位置（收起态） | 用途 |
|------|------|----------------|----------------|------|
| 画布 | 白底矩形 | (66,140)→(432,693)，366×553 | 画布变高，底缘约到 y≈860 | 落笔定位（必填） |
| 折叠钮 ∧ | 展开态可见 | x=17~36，y=755~760（~19×6px） | 不可见 | 收起工具面板 |
| 展开钮 ∨ | 收起态可见 | 不可见 | x=16~37，y=930~940 | 展开工具面板 |
| 撤销胶囊 ↩ | 两态都在 | x=37~109，y≈660~680（浮在画布内左下角） | x=37~109，y≈850 | 清空测试线 |
| 滑杆轨道 | 仅展开态 | y≈870，x=22~456（暗色，宽 434px） | 被画布吞掉 | 实测笔宽 |
| 橡皮 / 画笔 | 工具行内 | 工具行 y=750~766 | 工具行 y=930~940 | 工具态校验 |

工具行结构（展开态，y≈750~766，从左到右）：`∧ 画笔 橡皮擦 ✓`。

## 2. 初始状态

- 目标窗口为 **PC 微信小程序窗口**（非 scrcpy 投屏），窄高布局，逻辑尺寸约 499×979，后端实际截图为 DPI 放大后的分辨率（约 784px 宽，`112 候选 ≈ 4 行 × 28 列`）。
- 进入画板时面板可能是**展开态**或**收起态**两种之一，工具行会随开合**整体上下平移**（展开 y≈750，收起 y≈930）。
- 折叠钮/展开钮是**外表不同、功能相反、位置不同的两个独立按钮**（不是同一位可逆按钮）。
- 撤销胶囊是**浅灰底 + 细 ↩ 图标**，与白底画布对比度低。
- 滑杆轨道为暗色长条（灰度 <160 可被 strict 档识别）。

## 3. 难点

1. **折叠/展开钮极小**：∧/∨ 仅约 19×6px，且贴在最左（x=17~36，在画布左缘 66 之外）。候选网格步长 28px，按钮容易落在网格缝隙里，点网格点会点空。
2. **开合导致工具行整体平移**：折叠后工具行从 y≈750 下移到 y≈930。折叠钮探测阶段若沿用展开帧的候选网格，展开钮（收起态位置）根本不在网格内容里，导致「折叠→展开」成对复验失败。
3. **展开钮在折叠预算之外**：折叠扫描的回退预算只有画布下方 4 行（约 112px），而收起态展开钮在画布下方 ~237px（y≈930），4 行预算够不着，成对复验拿不到展开钮。
4. **撤销胶囊对比度低**：浅灰胶囊（≈240）与白底（255）差仅 ~15，接近内容判定阈值（12），加上细 ↩ 图标像素稀疏，撤销预扫描不易稳定命中。
5. **右侧「✓ 确认」不可逆**：盲扫必须始终规避工具行最右的提交控件，扫描面受限。
6. **窗口高度可被用户调整**：画布锚定窗口顶部（y≈140~693 不变），而工具行/撤销胶囊锚定窗口底部（窗口变高时整体下移）。窗口 979→1029 时工具行从 y≈930 下移到 y≈976，画布与工具行之间的空白带随之变化。因此所有定位必须以「画布相对坐标 + 内容行扫描」为准，不得用绝对 y 坐标。

## 4. 已确认的失败链

`折叠按钮识别失败` 的根因链（按当前代码 `toolbar_probe.py`）：

1. `_probe_fold_pair` 学习「折叠钮 + 展开钮」成对坐标，要求两钮都能命中并做一次往返复验。
2. `_learn_fold_pair_once` 在展开态先点折叠钮（点击→轨道消失）命中后，**仍用展开帧的候选网格**去找展开钮；而展开钮在收起态已经下移到 y≈930，网格内容里没有它 → 展开钮学不到 → `_probe_fold_pair` 返回 None → 折叠按钮标记失败。
3. 折叠按钮失败后，滑杆/橡皮/画笔等依赖「面板展开态」的步骤连带失败。

## 5. 重构方案（已实现）

- 折叠钮命中后**刷新帧**（重新识别画布 + 重算候选网格），再用**内容行扫描面**（收起帧内容行只有撤销胶囊行与工具行，右缘守卫继续挡「✓」）去学展开钮。
- 折叠/展开等小按钮点击改用**内容质心**而非网格点。
- 往返复验成功后恢复展开态候选网格，供后续滑杆/撤销/工具扫描；收起态重扫复用已学到的展开钮，避免重复盲扫。
