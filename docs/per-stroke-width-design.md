# 逐段笔宽控制设计（控件自动探测 + 容差合批）

> 状态：已评审定稿（2026-10-24，用户逐段确认）  
> 上游讨论：open-items 之外的走查反馈——「橡皮擦态误绘」「笔宽全程不变」「笔宽标定未触发」「展开/折叠态控件位置不同」「校准应自动、人工兜底」。  
> 关联：[focus-guard-and-multidevice-design.md](./focus-guard-and-multidevice-design.md)（守护/镜像）、[pen_calibration.py](../backend/app/executor/pen_calibration.py)、[pen_order.py](../backend/app/executor/pen_order.py)、[panel_control.py](../backend/app/executor/panel_control.py)、[service.py](../backend/app/executor/service.py)

## 0. 问题定性（现状代码事实）

1. **执行器从不点「画笔」按钮**：全程假定画板已是画笔态；校准记录只有 `slider/undo/fold` 三个点位，没有画笔/橡皮按钮位置。上一轮人工操作若留在橡皮态，机器人就直接用橡皮画。
2. **「笔宽不变」与「标定没跑」同源**：`autoWidth` 默认 `False` 时既不标定也不换宽（`width_table is None` → 全部笔画单档平铺）。
3. **双态位置错位的真 bug**：小程序工具面板折叠时**画笔/橡皮等工具按钮也会被收起或移位**（用户确认），而校准只存一套坐标、绘制时仅按画布矩形整体平移。拿展开态坐标点折叠态界面必然点错。折叠态下根本无法换笔，一切换宽必须「展开 → 操作 → 折叠」。
4. **逐段设宽的成本下界**（实测规模与延时）：真实画稿 2375–3415 段笔画；一次换笔 = 展开 0.45s + 点滑杆 0.25s + 折叠 0.45s ≈ 1.2s。逐段设宽 = +47~68 分钟，不可行；纯分档（现状）只有 K 级层次。折中为**逐段目标笔宽 + 容差合批**。

## 1. 控件自动识别：行为探测（behavior probing），不用图标模板

标定阶段自动学习工具栏，**不需要任何模板素材**，判据全部来自控件的可观测行为差异。所有探测点击只落在**画布外**；墨迹探测复用画布顶部「刻度带」（标定测试线机制已有，画完即撤）。

探测顺序（有依赖：折叠先于滑杆——折叠态找不到滑杆；撤销先于橡皮/画笔——清理依赖撤销）：

| 序 | 控件 | 判据 | 恢复 |
| --- | --- | --- | --- |
| 1 | 折叠按钮 | 工具条区域内画布外候选点逐个试；点击后截图看滑杆轨道出现/消失 | 再点一次切回 |
| 2 | 滑杆轨道 | 几何特征：细长水平暗段 + 圆形滑块（复用 ink_measure） | — |
| 3 | 撤销 | 刻度带先画一条基线 → 点候选 → 带内墨迹总量**减少** | 无需 |
| 4 | 橡皮/画笔 | 带内有线时点候选再压线描一遍：**线变白=橡皮**；新出深色墨=画笔 | 用已定位的撤销清理 |

**白拿的能力——画笔态指纹**：探测中以「选中/未选中」两态截取画笔按钮格，其背景亮度差即选中高亮特征（两个标量即可表达）。绘制期一眼可判当前是画笔还是橡皮，这是修复「橡皮态误绘」的判据来源。

**候选点来源**：画布下缘以下、窗口内的工具条区域，按连通暗块粗分格取中心（几十 px 网格即可），不依赖识别图标内容。

**人工兜底**：任一控件探测置信不足 → 仅该项提示用户在校准页单击/框选（从「框选 5 处」降级为「点 1 处」）。全部失败才回退旧单套坐标行为（见 §4）。

## 2. 双态工具位图与画笔态保障

校准记录从单套点位改为**按面板状态两套**：

```
toolsOpen:       { brush, eraser, slider, undo, fold, brushSelectedLum, brushIdleLum }
toolsCollapsed:  { 同上（折叠态各点位；折叠态无滑杆时 slider=None） }
```

- 当前实现中 `toolsCollapsed` 无自动产出路径（探测只在展开态完成），校准页亦无收起态标注 UI，仅可能由校准 API 透传写入；执行器的收起态画笔校验与 `fold_closed` 回退分支对自动探测的项目不生效，行为安全地降级为「展开后按展开位图校验」。

- 旧记录（无新字段）读取为 `None`：行为回退现状（单套坐标、无画笔校验），发 `task.warning`「旧校准：无法校验画笔态」，不阻塞续画。
- 绘制时先用 `PanelController.is_open` 判当前态，**取对应态坐标集**，不再跨态平移。
- **换笔时序固化**：展开(校验) → 校验画笔态，非画笔则点 brush 并复检 → 点滑杆到目标位 → 折叠(校验)。橡皮按钮绘制全程永不点击。
- **首笔前强制画笔校验**：按指纹判定；不是画笔就切换；复检仍非画笔 → 任务失败 `E_NOT_BRUSH`，**绝不下笔**。每次展开换宽后同样复检。
- 展开失败沿用当前笔宽继续画（保留现有降级），但画笔校验在折叠态只做「不劣于基线」的宽松判定（工具格不可见时不强判）。

## 3. 逐段目标笔宽（连续值，百分位映射）

每段笔画得到连续目标笔宽，不再压成 5 档：

1. 密度信号沿用「1px 栅格化 + `boxFilter` 大窗口线密度」（[pen_order.py](../backend/app/executor/pen_order.py) 已有，暗部=线密）。
2. 全笔画密度取**百分位排名** r ∈ [0,1]（分位而非 min-max，抗离群）。
3. **r 即目标滑杆行程**：密→粗端、疏→细端。恒等映射天然把笔画均匀铺满滑杆全域，滑杆非线性无需补偿；实测宽度表（[pen_calibration.py](../backend/app/executor/pen_calibration.py) 的 `WidthTable`）只保留「滑杆有效性判定」（spread ≥ `MIN_SPREAD_RATIO`），spread 不足照旧回退单细笔。
4. **先细后粗**（2026-10-30 用户裁决改向）：绘制序列按目标行程从小到大推进——起笔最细档，暗部（最粗）最后画、压在最上层；也保证笔宽标定后首笔不复用残留的粗档。断点兼容：`exec_params.widthOrder=2` 标记新笔序，旧断点（无标记且多档表）续画时重置游标重画。

## 4. 容差合批（换笔次数唯一旋钮）

- 行程 [0,1] 按容差 `tol` 分桶：`bucket = floor(r / tol)`，默认 **tol=0.05** → ≤20 桶；空桶跳过。
- 桶内最近邻贪心排序（`nearest_order_paths`），跨桶保持细→粗。
- **仅在进入新桶时点一次滑杆**，点位取**桶下缘**（`bucket*tol`）：沿用「实际宽度绝不粗于计划」约定，桶内偏细有界 ≤ tol。
- 成本上界 ≈ 20 × 1.4s ≈ 28s（对比逐段 +68 分钟）。
- 参数变更：删除 `widthTiers`，新增 `widthTolerance`（0.02–0.20，默认 0.05，前端滑杆「换宽粒度」，越小越细腻越慢）；**`autoWidth` 默认值改为 `True`**。`from_dict` 忽略旧 `widthTiers` 字段。
- **续画一致性**：分桶序列 = f(笔画集, 参数, 宽度表) 纯函数，续画重算逐位相同，`cursor_path` 语义不变（与现状 tier 重排同构）。

## 5. 数据与接口

- `CalibrationRecord` 增加 `toolsOpen` / `toolsCollapsed` 两 JSON 字段（`db.py` 迁移表沿用现有 `ALTER` 补列模式）。
- 校准 API：`POST /api/calibration` 接受新字段；自动探测产物与人工兜底产物同构，人工可覆盖单项。
- 标定/探测进度全部走既有 `task.warning` 通道，前端零改动即可见。

## 6. 兜底与失败语义

| 场景 | 行为 |
| --- | --- |
| 单控件探测置信不足 | 该项转人工（校准页单击），其余照常自动 |
| 面板展不开 | warning + 沿用当前宽度继续（现状保留） |
| 首笔前画笔态校验失败 | `FAILED E_NOT_BRUSH`，不下笔 |
| 滑杆 spread 不足（不可调宽） | 单细笔回退（现状保留） |
| 旧校准记录 | 单套坐标旧路径 + warning，不阻塞 |
| 探测污染画布 | 不可能：探测点击全在画布外；刻度带清理判定改「相对基线」（带内基线墨量 ≤ baseline+ε 即通过，避免用户画布本有画时误清/误判） |

## 7. 测试与验收

- 单测（fake probe/mouse，合成工具栏截图夹具）：控件行为探测各分支、双态坐标选择、画笔指纹判定、分桶序列与容差合批、续画重算一致性、`E_NOT_BRUSH` 路径、旧记录回退。
- 回归：`tests/manual/mirror_e2e` 夹具增加合成工具栏（含折叠/展开双态），覆盖「橡皮态开局被纠正」「换宽 ≤ ceil(1/tol) 次」。
- 全量 `pytest` 通过为提交门槛。
- 真机项挂 open-items §1A 族：真实小程序上探测正确率、换宽后实测宽度抽验（刻度带法）。

## 8. 明确不做（YAGNI）

- 图标模板库/OCR/检测模型（行为探测已覆盖需求）。
- 逐段物理设宽（成本 +68 分钟不可行，§0.4）。
- 多画板风格适配层（当前只服务霸王茶姬小程序；探测本身是画板无关的）。
