# 窗口尺寸变化下的自动校准断裂与韧性方案（2026-10-31 真机实录）

状态：B1–B6 已实施（含单测），待真机回归。触发事件：用户把小程序画板窗口从 720×1353 缩小（物理 539×988），随后退出重进画板页。自动校准与后续绘制在每个环节连环失败，最终一张 208 笔的画全部以 23px 最粗档画成黑块。这张废画把「窗口尺寸与校准基准不一致」时的全部薄弱点暴露了一遍，每个断点都有当场取到的数据。

## 断点清单

### B1 失败项回落旧帧坐标，只平移不校验

`_merge_partial_bitmap`（[service.py](file:///d:/Workplace/ChageeCupDrawing/backend/app/executor/service.py#L1208-L1248)）把本轮没探到的控件回落到上一次校准的坐标，再按画布位移 `(dx, dy)` 平移。窗口尺寸变了以后，工具条相对画布的位置不随画布平移——旧帧 `fold=[40,1291]` 直接进了 1039 高的新帧，点永远落空。落库前没有任何「坐标必须在当前帧内」的检查。

这一条是整张废画的直接原因：绘制时展开面板要点折叠按钮，坐标出帧 → 展开失败 → 跳过笔宽标定。

### B2 `savedSteps` 虚报，半残校准对使用者呈现为成功

同一段失败落库代码（[service.py](file:///d:/Workplace/ChageeCupDrawing/backend/app/executor/service.py#L1093-L1108)）：`savedSteps` 按 `merged` 是否非空统计，`merged` 含 B1 回落的旧值，于是 `fold/slider/eraser` 同时出现在 `savedSteps` 和 `failedSteps` 里。前端和使用者无法从返回值判断「这份校准到底能不能画」。

### B3 部分成功路径落库的句柄/标题是错的

`_persist_probed_calibration` 用 `base.hwnd`（上一条记录的句柄），不是本轮实际探测的窗口（[service.py](file:///d:/Workplace/ChageeCupDrawing/backend/app/executor/service.py#L1084-L1092)）。画板页重进后句柄必变，这次落库的 `hwnd=3017530`、`window_title=''` 直接让后续 `clear-canvas` 报 `E_WINDOW_LOST`，也绕过了按标题重绑的自救路径（标题为空）。

### B4 「单细笔绘制」回退不改滑杆，告警与事实相反

告警文案（[service.py](file:///d:/Workplace/ChageeCupDrawing/backend/app/executor/service.py#L1834-L1837)）说的「单细笔」只表示不做分档，笔宽 = 滑杆停留位置。滑杆位置是上一环节（标定的刻度带测试或探测）留下的未归位状态，23px 也照样叫「单细笔」。更根本的：`autoWidth=true` 且标定失败时仍然放行落笔，宽度处于不可知状态。

### B5 常驻悬浮控件触发脏检误报

悬浮撤销按钮是画板页的常驻 UI，固定压在画布左下（这次 1892 px 墨）。新窗口的 L2 空白基线为空，L1 绝对判据（阈值 64 px）必然判脏，逼着每次都走 `confirmDirtyProbe`。校准流程自己也会画测试线、点控件，脏检的假阳性把「强制放行」变成了习惯，真正的脏画布反而失去门禁意义。

### B6 探测残留墨迹无人负责

`E_PROBE_UNCLEANED` 的字面含义是「探测画的线没撤销干净」，但接口把这当作可继续的告警。这次画布左上角残留一条 65px 黑线，自动清空（撤销注入）、注入拖拽橡皮全部无效，最后靠用户徒手擦除。注入拖拽对小程序画板不可用是今天实测出来的硬约束，凡是依赖拖拽的自愈路径都不可靠。

## 方案

按「先止血、再造血」排序，前四条都是小改动。

1. **帧内校验门（B1）**：`_merge_partial_bitmap` 与失败落库路径在写入前逐控件检查坐标 ∈ `[0, frame_w] × [0, frame_h]`，越界的置 `None`。旧坐标不再伪装成可用能力。同时给画布坐标加同源校验（窗口缩小后画布本身仍可识别，这没问题）。
2. **如实的失败上报（B2、B3）**：`savedSteps` 只列本轮学到或经帧内校验有效的字段，与 `failedSteps` 互斥；落库 `hwnd`/`window_title` 用本轮实际目标窗口。前端拿到 `failedSteps` 非空时把校准标成「可绘制：否」，给出缺什么、怎么补。
3. **落笔前宽度门禁（B4）**：`autoWidth=true` 且 `width_table=None` 视为宽度不可控，默认阻断并提示「先完成校准或手动把滑杆放到最细档后关闭自动变粗」；若滑杆轨道已知，先尝试单击轨道最左端归位（点击可靠，拖拽不可靠），归位成功才继续。告警文案与实际行为对齐。
4. **探测残留显式上报（B6）**：`E_PROBE_UNCLEANED` 时返回残留墨量与位置，前端引导用户手动清理；清理前禁止起绘。不再让残留线静默进入成品。
5. **常驻控件脏检豁免（B5）**：撤销按钮坐标已知（悬浮态锚定画布左下，可由画布矩形推算），脏检墨量统计时把该矩形从画布区域挖掉。豁免名单随校准更新，避免按钮漂移后漏判。
6. **窗口规格指引（体验）**：校准页开始前检测当前窗口与客户区，对照建议尺寸（本次画板画布需要窗口约 720×1353；屏高不足时明确告知「画布将按当前窗口分辨率重算，细节上限下降」而不是事后猜）。窗口高度受工作区钳制是系统行为，接受它——校准以当前帧为准本来就是正确姿势，不该假装能回到 1353。

## 验收标准

- 构造窗口缩小 + 面板任一态，走一次自动校准：要么完整成功，要么失败项字段为 `None` 且接口标「不可绘制」；库内不存在出帧坐标、错误句柄。
- 半残校准后直接起绘被阻断，提示指向具体缺失项；不再有「单细笔」告警配最粗笔宽的组合。
- 画板页窗口尺寸变化后的完整链路（校准 → 规划 → 绘制 → 成品无残留线、笔宽 = 标定值）无需任何手工修库即可走通。

## 风险与观察点

- 帧内校验会把「按钮暂时被遮挡」误杀成坐标无效：豁免路径保留，但要求人工确认并打 `source=manual` 标记，不再与自动探测值混淆。
- 单击轨道最左端归位滑杆依赖小程序滑杆的点击跳变行为，今天只在观测里确认过thumb 位置跟随点击，执行链路里需真机回归。
- 悬浮撤销按钮的推算位置在画布滚动/缩放态可能失效，豁免区挖除宁小勿大（漏判脏检会误伤用户，多判脏只多一次确认）。
- 附注：本次排查初期观测脚本报过 431×790 的错误窗口尺寸，原因是脚本未声明 DPI-aware（系统缩放 125%）。后端校准链路自带 `dpi_scale=1.25` 处理、未受影响，但所有外围观测脚本都必须先 `SetProcessDpiAwareness`，否则量到的每个坐标都是错的。
