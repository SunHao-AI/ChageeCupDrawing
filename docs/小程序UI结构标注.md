# 小程序画板 UI 结构标注（用户截图实测）

> 本文依据用户提供的 4 张小程序截图整理，记录画板的 3 种初始状态与各控件
> 的精确位置，供自动校准（`toolbar_probe.py`）的控件识别与坐标定位使用。
> 截图存于 `docs/小程序UI/`。

## 1. 截图与窗口尺寸

- 截图逻辑尺寸 **521×979**（用户截图）。
- 后端实际截图为 DPI 放大后的分辨率（历史观测约 720×1251，宽高比例非等比，
  约为 x×1.38 / y×1.28）。**所有坐标必须以「画布相对偏移 + 内容行扫描」为准，
  不得用绝对像素**——窗口尺寸会变，画布锚定窗口顶部、工具行锚定窗口底部。

画笔/橡皮擦在其右侧同一行（y≈718-777）。

## 4. 关键洞察（对探测逻辑的影响）

1. **滑杆是上下文相关的，不是常驻控件**：
   - 选中「画笔」时，黄色框区域是**笔宽滑杆**；
   - 选中「橡皮擦」时，黄色框区域是**橡皮擦大小滑杆**。
   - 未选中画笔/橡皮擦时，滑杆可能**不出现**。
   - 因此 `_track_visible()` 用「滑杆轨道是否存在」判断展开/收起态**不可靠**——
     撤销预扫描阶段未选中工具 → 无滑杆 → 轨道检测失败 → 折叠扫描方向被误判。
2. **折叠钮极小**（绿框 x 9-53 ≈ 44px 宽，y 724-768 ≈ 44px 高），贴画布左缘外，
   与画笔/橡皮擦（蓝框 x 120-239）同处一行、左右相邻。
3. **撤销胶囊浮在画布内左下角**（红框横跨画布底缘 y≈701），不是画布下方的独立行。
4. 控件纵向顺序（展开态，从上到下）：
   `撤销(666) → 折叠/画笔/橡皮擦(746-748) → 滑杆(869)`，三者相距约 80px 与 120px。

## 5. 两态控件标注（2026-10-29 用户截图实测，501×978）

> 截图 501×978 → 后端窗口截图 720×1406 为**等比**放大（×1.438），下表两套坐标并列。
> 图一（折叠态）蓝=画布 红=撤销 黄=重做 绿=展开(∨) 紫=画笔 黑=橡皮擦；
> 图二（展开态）灰=折叠(∧) 棕=滑杆。
>
> **⚠ 坐标系仅对本机当前窗口有效**：501×978 是此电脑打开小程序的默认大小，
> 窗口宽高后续可能被用户调整，其他型号显示器打开的尺寸也可能不同。表内绝对
> 坐标只能作为**结构参照**（谁在谁的哪一侧、隔多远），不得写死进代码；探测
> 必须维持「画布锚定 + 窗口底缘锚定 + 内容行扫描」的相对定位策略（§1 的
> 结论依旧成立）。相对量里可迁移的是**结构不变量**：撤销/重做同行相邻、
> 工具行在胶囊行下方一行且贴左缘起排、滑杆在工具行下方贴底、控件均带
> DPI 缩放（同窗口内同比变化）。

### 5.3 滑杆语义（用户确认）

**滑杆随选中的工具变化**：选中「画笔」时调节**画笔粗细**，选中「橡皮擦」时调节
**橡皮擦大小**。自动变粗流程在压滑杆前必须确认当前选中的是画笔，否则改的是橡皮大小。

### 5.4 对探测逻辑的直接推论

1. **撤销行/滑杆行都在画布外下方**（本窗口折叠态 y≈1235 / 展开态 y≈1253，而现有
   扫描面只到画布下缘 +~250px 的内容行预算、实际点到 y=786-982 的空白竖带）。
   因窗口高度可变，修复不能按「画布下缘 + 固定像素深度」扩面，应按**窗口底缘
   锚定**：底部控件簇（胶囊行+工具行+滑杆）整体贴底排布，从底缘向上扫内容行
   天然覆盖任何窗口高度下的工具簇（本窗口：撤销距底缘 ≈171px）。
2. **折叠态撤销/重做是并排两个胶囊**（撤销 x≈60、重做 x≈153）：点中重做会把撤销
   掉的测试线原样补回，镜像剔除（`_mirror_excluded`）按「撤销右邻一步长=重做」
   的先验与实测 +93px（约 3 个 28px 步长）不符，需按胶囊实测间距复核。
3. **展开态轨道是黑色实线**：strict 档失败更可能是搜索带/分组高度问题而非灰度问题，
   旧结论「浅灰轨道 strict 恒失败、必须撤销锚点走宽松档」需要用本轮 debug 截图复核。
