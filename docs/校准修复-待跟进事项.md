### A1. 漂移门禁放行面板开合后的完整绘制链路 ❗阻塞级

- **描述**：真机跑通「清空画布 → 开始绘制」全链路：倒计时 → 工具条探测 → 笔宽标定 → 逐段换宽绘制 DONE。
- **背景**：事件表实锤此前真机三次全部 `FAILED: E_CANVAS_DRIFT 画布位置变化 3.9%`——校准存面板收起态画布矩形（765px 高），开画时自动变粗展开面板（735px），IoU 96.08% 被漂移门禁（默认 allowDrift 0.02）误杀，**探测与笔宽标定从未执行**，这就是"没有笔宽校准、笔迹无粗细变化"的根因。已在 [service.py](file:///d:/Workplace/ChageeCupDrawing/backend/app/executor/service.py) 加 `_is_panel_state_change`：左/上/宽不动仅高度变化判为面板开合，放行 + warning「工具面板处于展开态…已按当前画面继续」。
- **要求/核对点**：
  1. 不再出现 `E_CANVAS_DRIFT`（窗口真移动/缩放仍须拦，既有 C1 测试兜底）；
  2. 出现 5 条「已识别 …」+「开始笔宽自动标定」→ 完成后笔迹有粗细变化；
  3. 探测期间校准页步骤流每步实时刷新（含「已试 k/n 个候选」进度）；
  4. 探测明显变快：折叠钮盲扫按「有内容的行优先」（预算内重排序，锁定测试 2 条），鼠标不再先在空白区爬行。
- **完成判据**：一次 DONE + 刻度带抽测线宽与 `width_table` 偏差 ≤±15%（即 `open-items.md` §1A.6 同步闭环）。

## E. 已知边界备忘（非缺陷，勿当 bug 修）

- **撤销预扫描安全区**只有一条硬约束「候选 x < 画布左缘」：初始态下可能误点最左「画笔」标签（与 brush_entry 等效、可接受），探测结束不自动退回初始态——刻意设计。
- **滑杆宽松档仅经 `_locate_slider` 生效**；`_find_slider`（面板开合 oracle）必须保持纯 strict，否则收起态工具格会被相对判据误当轨道。改前先看 `test_relaxed_slider_requires_undo_anchor_and_rejects_full_width`。
- **`_ensure_drawing_tool` 的「带内自有线即视为画笔态」守卫**：防同位重描误判引发全网格盲点；删除前需理解 `E_PROBE_UNCLEANED` 的撤销预算语义。
- **折叠钮盲扫提速只做预算内重排序**：候选集合恒等于「距画布最近 N 行」——更远的底部行可能有文字/贴纸等不可逆标签，只能由带差分门控的 brush_entry 处理。锁定测试：`test_fold_scan_reorders_within_budget_only`。
- **倒计时期间不抢前台**是刻意改动（用户要看秒数）；末段稳定窗才 activate。若有测试或用户预期「点开始就该切窗口」，以此为准修订。
- **校准页横幅判据**：`!(slider || toolsOpen)`（§1B.1 方案 A 定案），单列语义保持「人工标注」，探测结果不回填单列。
